# Codex実行プロンプト

以下の文章をCodex CLIへ貼り付けて使用してください。

---

`docs/Codex_Iteration01_BOM_CAB_to_Excel_Instruction.md` を最優先の開発指示書として読み、記載された要件に従って「BOM CAB設定仕様書生成ツール」を実装してください。

## 作業方針

1. まず指示書、リポジトリ内の既存ファイル、提供サンプル `templatemaker` の構成を確認してください。
2. 既存の `TemplateMaker.exe` およびDLLは実行・逆コンパイルせず、参照資料としてのみ扱ってください。
3. 最初に `templatemaker/temp` の展開済みデータを使い、MANIFEST解析、XML解析、データモデル、Excel出力を完成させてください。
4. その後、Windowsの `expand.exe`、7-Zip、cabextract等を利用するCAB展開アダプターを実装してください。
5. 不明なXML項目を推測で変換せず、元の要素名と値を必ず保持してください。
6. 実装と並行して単体テスト・結合テストを作成し、提供サンプルの1グループ・4監視項目が正しく出力されることを検証してください。
7. Excelには指示書で指定されたシート、書式、数式インジェクション対策を実装してください。
8. Python CLIとして完成させ、README、設計文書、対応監視タイプ一覧も更新してください。

## 実行前に行うこと

- 現在のディレクトリ構成を確認する。
- 指示書を全文読む。
- サンプルファイルが存在するか確認する。
- 既存コードがある場合は、破壊的に置き換えず内容を把握する。
- 実装計画を `docs/development_plan.md` に記録する。

## 実装中のルール

- Python 3.11以降を対象とする。
- Excel生成には `openpyxl` を使用する。
- 型ヒントを付ける。
- 例外を握りつぶさない。
- サンプル固有値をハードコードしない。
- OS依存処理を解析処理から分離する。
- 一つの巨大なファイルにまとめず、指示書の推奨構成を基本に分割する。
- 各主要機能を実装した時点でテストを実行する。
- lint、型チェック、テストの実行コマンドをREADMEに記載する。

## 最終確認

作業完了前に、少なくとも次を実行してください。

```bash
python -m pytest
```

利用する設定に応じて、次も実行してください。

```bash
python -m ruff check .
python -m mypy src
```

提供サンプルに対して実際にExcelを生成し、次をプログラムで再確認してください。

- 必要な全シートが存在する。
- BOMバージョンが8.0である。
- グループ名が「ディスクパフォーマンス監視」である。
- 監視項目数が4である。
- MON01の監視名、監視間隔、注意判定、危険判定、ObjectNameが指示書の期待値と一致する。
- 生成したExcelをopenpyxlで再オープンできる。
